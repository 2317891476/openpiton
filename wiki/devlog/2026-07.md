## 2026-07-01 -- coh_ipi64 progress-only long-run mode

- Added `COH_IPI64_PROGRESS_ONLY` to the Verilator harness so long
  `coh_ipi64.c` sweeps can print `COH_IPI64_PROGRESS main_time=<n>` without
  enabling the small VCD signal sampler.
- This keeps the next root-cause step ordered: first reproduce the real
  messages-monitor fail string and approximate `main_time` with a low-overhead
  run, then rebuild the harness with a narrow `COH_IPI64_SMALL_VCD_START/STOP`
  window around that time.
- The earlier full small-VCD and short-window runs remain useful for exclusion,
  but they are too slow for probability sweeps because even dormant hierarchical
  signal access adds measurable overhead on the 8x8 `-O0` model.

## 2026-07-01 -- coh_ipi64 short-window VCD excludes TILE36 BootROM/CSM hypothesis

- Ran the short `main_time=22000000..24000000` `coh_ipi64` VCD window for
  seed 0 and decoded the older `23535xxx` TILE36 event. The access is an
  IFILL response for BootROM address `0xfff101000c`, not a CLINT MSIP/IPI
  response (`0xfff1020000` range).
- The TILE36 CSM state at `23535250` is a read-only path:
  `l15_csm_req_val_s2=1`, `read_val_s2=1`, `write_val_s2=0`, `ghid_val_s2=0`,
  and `wr_en_s2=0`. The NoC2 message is `MSG_TYPE_DATA_ACK` with `mshrid=1`
  and `noc2decoder_l15_hmc_fill=0`, so it is not an HMC/CSM refill write.
- This rules out the concrete hypothesis that the old
  `TILE36 L15_CSM REQ MON` / `SIGDIE` line was caused by a BootROM or CLINT
  device response being misclassified as a CSM/HMC fill. The next root-cause
  capture must trigger on the actual messages-monitor fail condition rather
  than the last high-volume monitor line printed before abort.

## 2026-07-01 -- coh_ipi64 small-VCD compile fix

- Fixed the `coh_ipi64` small-VCD harness compile path for the local Verilator 5
  generated headers. `VlWide<N>` uses an unsigned size template parameter, so
  the helper that extracts 64-bit chunks from raw NoC2/CSM wide words now uses
  `std::size_t N`.
- This is still a diagnostic harness change, not an RTL behavior change. The
  immediate test remains the short `main_time=22000000..24000000` capture of
  TILE36 raw NoC2 flits, CSM `write_val_s2 && !ghid_val_s2`, and BootROM/CLINT
  return flits.
