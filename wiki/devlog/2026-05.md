## 2026-05-29 -- P3 UART serial port hang root causes identified (Build 37-38)

- **AFE Deadlock**: Identified that the default OpenPiton bootrom `init_uart()` sets `UART_MODEM_CONTROL = 0x20` (AFE = 1, Autoflow enabled). Since the P3 board only routes `TXD` (CM59) and `RXD` (CN59) and lacks physical flow control signals (`CTS`/`RTS`), enabling AFE locks the transmitter waiting for a CTS assertion. Setting `UART_MODEM_CONTROL = 0x00` in Build 38 bypassed this but was not sufficient on its own.
- **Address & Data Lane Mismatch**: Found that the 64-bit `noc_axilite_bridge` expects read data on byte lane 5 when accessing LSR (offset 5, address `0xFFF0C2C005`), and performs a right shift of 40 bits: `(m_axi_rdata >> 40)`. However, the AXI transaction address is translated in `uart_top.v` via `(addr << 2) | 13'h1000` to `0x1014`, causing the 32-bit Xilinx UART IP to return the LSR register on the low 8 bits (`s_axi_rdata[7:0]`). When this 32-bit bus is connected to the 64-bit bridge and zero-extended, the right shift by 40 bits discards the valid register data and returns `0x00` to the CPU.
- **Proposed Solution**: In `uart_top.v`, replicate the 8-bit read data byte across all 8 byte lanes of the bridge's 64-bit read data bus (i.e. `.m_axi_rdata({8{core_axi_rdata[7:0]}})`). This ensures that the bridge always extracts the correct register byte regardless of the address offset lane.
